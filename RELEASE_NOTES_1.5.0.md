# CharmedChars v1.5.0 — Ender Dragon Logo Block

## Release Date
2026-04-23

## Overview

v1.5.0 introduces the Ender Dragon finale: a randomly-colored logo block drops above the exit portal when the dragon dies, and placing that block in The End then hitting it with a gold or pyrite tool transforms it into a matching colored shulker box pre-filled with configurable loot. All three custom item providers (ItemsAdder, Oraxen, Nexo) are fully supported and tested. Nexo is no longer marked as untested.

This release also fixes a critical build issue where the shadow JAR was being silently overwritten by the thin JAR, causing `NoClassDefFoundError` for Kotlin coroutines at server startup.

---

## New Features

### Ender Dragon Logo Block Drop
- On Ender Dragon death, a logo block in a random color (cyan, magenta, or yellow) drops on the flat end stone just outside the fountain (X=5.5, Z=0.5, Y = ground + 2)
- Positioned outside the fountain to avoid two hazards: exit portal blocks (±2 from centre) teleport item entities to world spawn; the dragon egg (first kill) has a non-full hitbox that lets items slide off onto those portal blocks
- Drop is world-sourced from `event.entity.world` — works in any End dimension, not hardcoded
- No killing blow required — fires for any dragon death including `/kill`
- Color selected via `BlockColor.getRand()` from the three logo colors

### Logo Block → Shulker Box Transformation
- Placing a logo block in The End and hitting it with a gold or pyrite tool (no Silk Touch) transforms it into a colored shulker box matching the block color:
  - Cyan logo → Cyan Shulker Box
  - Magenta logo → Magenta Shulker Box
  - Yellow logo → Yellow Shulker Box
- Shulker box is pre-filled with items from `logo-block.shulker-contents` in `config.yml`
- Default contents: 4 Ghast Tears
- Contents fully configurable — any valid Minecraft material and quantity

### Config Section for Shulker Contents
```yaml
logo-block:
  shulker-contents:
    - materialName: "GHAST_TEAR"
      quantity: 4
```
Multiple entries are supported. Invalid material names are silently skipped. If the section is absent or empty the default (4 ghast tears) is used automatically.

### Logo Block Definitions for All Providers
- **ItemsAdder**: Logo block items and textures were already present; now registered and functional
- **Oraxen**: Logo block YAML definitions, block/item model JSON files, and texture files now generated by `/oraxensetup`
- **Nexo**: Logo block YAML definitions, model JSON, and texture files now generated by `/nexosetup`

## Fixes

### Shadow JAR Build Fix
- The `jar` task and `shadowJar` task were both outputting `CharmedChars-X.X.X.jar`, with `jar` running last and overwriting the fat JAR with the thin JAR (no bundled dependencies)
- Fix: `tasks.jar { enabled = false }` — thin JAR is suppressed entirely; `build/libs/` contains only the deployable shadow JAR
- Previously caused `NoClassDefFoundError: kotlinx/coroutines/CoroutineScope` at server startup

### Shulker Inventory Population Fix
- `shulkerState.update(true, false)` was being called after `inventory.addItem()`, which writes the empty snapshot back over the live tile entity — wiping the added items
- Fix: removed the `update()` call; `inventory.addItem()` on a live (placed) block modifies the tile entity directly and persists immediately

### Oraxen Logo Block Texture Fix
- Oraxen setup generated item definitions and textures for logo blocks but did not generate the required block model or item model JSON files
- Fix: model generation loop now includes `cyan_logo`, `magenta_logo`, `yellow_logo`

### Oraxen Double-Processing Visual Glitch Fix
- When a player hit a logo block with Oraxen, both `PlayerInteractEvent` and `BlockDamageEvent` fired for the same click
- The processing guard released the block key before the 2-tick deferred transformation completed, allowing `BlockDamageEvent` to start a second transformation mid-replacement — causing a block-break animation and invisible shulker
- Fix: the processing key is now held in `processingBlocks` until the full 2-tick chain completes, then released in a `finally` block

## Post-Release Fixes

### Logo Block Drop Location Fix
- The exit portal blocks teleport item entities to world spawn. After the first dragon kill the dragon egg is present — its non-full hitbox causes items to slide off onto the surrounding portal blocks even when spawned directly above the pillar
- Fix: drop moved to the flat end stone at X=5, Z=0 — outside the fountain structure entirely, beyond the range of `dropItemNaturally`'s scatter

### Nexo Resource Pack Size Fix
- Adding logo block textures pushed the Nexo resource pack over the server upload size limit
- Fix: `NexoSetup` now sources block textures from `pack-oraxen/` (256×256) instead of `pack/` (512×512)
- After updating the JAR: run `/nexosetup force` then `/nexo reload` on the Nexo server

### Build Toolchain Upgrade (JDK 25)
- Gradle 8.14.4 does not support JDK 25; upgrading JDK caused the build to fail with `IllegalArgumentException` in Kotlin's `JavaVersion.parse`
- Upgraded to Gradle 9.4.1 and Shadow 9.4.1 (no server or runtime impact)

## Upgrade Instructions

**From v1.4.2:**
1. Stop the server
2. Replace `CharmedChars-1.4.2.jar` with `CharmedChars-1.5.0.jar`
3. Start the server — the new `logo-block` config section will be written automatically if absent
4. For Oraxen servers: run `/oraxensetup force` then `/oraxen reload all` to regenerate logo block models and textures
5. For Nexo servers: run `/nexosetup force` then `/nexo reload` to regenerate logo block assets
6. For ItemsAdder servers: run `/iasetup force` then `/iazip` if logo block items were not previously available

**No database or configuration migration needed** — drop-in replacement.
